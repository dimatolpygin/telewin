# Структура прайса «Мемо Фора»

> **ВАЖНО: формат данных может отличаться.** Поля и формат выгрузки в Форе настраиваются клиентом,
> и по факту уже приходили два разных набора колонок:
> - `samples/2026-07-06T06-25-47.xlsx` — **11 колонок**, 8 389 строк (со штрихкодом, категорией, видом товара);
> - `samples/boevoy_прайс_2026-07-08.xls` — **8 колонок**, 11 888 строк (БЕЗ штрихкода, категории и вида товара) — это то, что реально летит на FTP с `WFormat=11`.
>
> Парсер обязан определять раскладку колонок сам (по числу колонок / эвристике), а не полагаться
> на фиксированный порядок. Таблица ниже описывает 11-колоночный вариант.

## Выгрузка

- Полная команда (с автологином в Фору, без окна ввода пароля):
  `C:\Fora4S\fora.exe User="***" PASSWORD="***" mode=10 WFormat="11"`
  - `User` / `PASSWORD` — учётка внутри «Мемо Фора» (значения — в `доступы.txt`, вне репозитория).
    БЕЗ них программа при старте показывает окно логина и из Планировщика зависает в статусе «выполняется».
  - `mode=10` — режим выгрузки прайса для Web
  - `WFormat=11` — номер формата выгрузки («Остатки товара», приоритет 11)
- Путь к программе: `C:\Fora4S\fora.exe`
- Также в формате выгрузки должна стоять галка «Без выдачи сообщений» (вкладка «Общие»), чтобы не всплывало окно «файл выгружен».
- Задача в Планировщике: «Выполнять только для вошедших пользователей», настроить для Windows 10, галка «Разрешить выполнение по требованию» включена. ПК должен быть включён и с активной сессией.
- Подтверждено: 2026-07-10 автозапуск из Планировщика отработал, файл долетел на FTP.
- Формат файла: **`.xls`** (BIFF, старый Excel, Composite Document), кодировка cp1251, автор MF4x4.
- Имя файла: по дате-времени ISO, например `2026-07-08T15-56-31.xls`.
- Объём: ~8389 позиций, ~2.4 МБ.
- Заголовков строк нет — данные с первой строки, колонки маппятся по позиции.

## Важные замечания для бота

- **Price = цена реализации (розничная)** — безопасно показывать покупателю. НЕ закупочная.
- **Остаток общий (кол.7) НЕ равен сумме кол.8 + кол.9, и это массово.** Замерено парсером
  на этапе 1: расходится **572 позиции из 11 888** в боевом файле и **630 из 8 389** в xlsx
  (например «Болт M 5*12»: общий 424 против 158+265=423). Это не единичный курьёз, а свойство
  данных Форы. Колонки берём как есть; своё число вместо учётного не подставляем.
- Остатки бывают **дробными** — единица измерения не всегда штуки (метры, килограммы).
  Не типизировать остаток как целое.
- Десятичный разделитель в цене — запятая (`0,5`), учесть при парсинге. В `.xls` от Форы цена
  лежит числовой ячейкой, и SheetJS отдаёт её сразу как `3.5`; строковый вид парсер тоже понимает.
- **Артикул бывает пустым** (в пустышке с FTP такая строка есть). Ключом считать его нельзя.
- Идентификатор для мультибазы / объединения — **штрихкод (SCod3)**, он заводской и совпадает между базами.
- Настройки полей/формата в Форе гибкие (клиент писал: поля и формат корректируются).

## Пустышка 50 КБ — чем на самом деле опасна

Разбор на этапе 1 (`price:parse samples/пустышка_2026-07-13T08-39-49.xls`):

- Это **не битый файл**. Валидный Composite Document, автор `MF4x4`, code page 1251 —
  та же Фора, что и боевые выгрузки.
- Раскладка правильная, 8 колонок, **122 позиции** вместо 11 888. Судя по товарам
  («Автом. выкл.», «DIN рейка», «Шина нулевая») — выгрузился один отдел, электрика.
- Товары, цены и остатки в ней **настоящие**. Парсер разбирает её без ошибок, и это правильно.
- Опасность — в правдоподобности: загрузи её бот, и он честно ответит «нет в наличии»
  про 11 766 товаров. Ровно то враньё, ради недопущения которого затевался принцип «не врать».
- Ловится **только** порогом строк и сравнением с прошлым импортом → этап 2.
