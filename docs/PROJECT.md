# PROJECT — telewin / «Домашний мастер»

## Клиент и контекст

- Клиент: telewin. Сеть хозяйственных магазинов «Домашний мастер», сайт masterberez.ru.
- Две торговые точки: **Микрор-н** и **п.ш. Березовская**.
- Товароучётная программа: **«Мемо Фора»** (memo4x4.ru), десктопная, Windows. Стоит на ПК в первом магазине, там общая база. Клиент подключается по VPN / удалённому рабочему столу.
- Заказчик technically грамотный, но не программист. Боится расхождения ожидание/результат — с ним держим честную планку по границам возможностей.
- Реализацию пишет Claude Code. В ТЗ клиента фигурировал n8n, но он одобрил любой способ. Боты делаем на **Node.js** (гибче для поиска и синонимов, чем n8n).

## Этапы (по нарастанию сложности)

1. **Прайс + боты VK/MAX** (текущий). Бот отвечает покупателям о наличии и цене.
2. **Обмен пакетами между магазинами** через «Мемо Фора». Самое сложное: пакет только через меню → RPA (эмуляция кликов), отладка на живой программе. Отложен.
3. **Прогноз продаж + автозаявки поставщикам**. Аналитика по данным за 5+ лет. Сложность в расчётах, не в программе.
- Отдельно, вне линии: контент для соцсетей (клиент интересовался).

## Архитектура Этапа 1 — три звена

1. **Выгрузка (на ПК первого магазина).** «Мемо Фора» командой `fora.exe mode=10 WFormat=11` выгружает прайс «Остатки товара» (формат 11). Файл `.xls` (BIFF, cp1251), имя по дате-времени ISO. Запуск по расписанию — Планировщик заданий Windows.
2. **Доставка (FTP).** Программа сама отправляет файл по FTP на наш сервер (пассивный режим, порт 21). Строка: `ftp://foraprice:***@87.58.210.46:21/price/`. Проверено сквозным прогоном 2026-07-08 — файл долетает.
3. **Бот (наш сервер).** Node.js, режим polling (webhook и домен не нужны). Читает свежий прайс, ищет товар, отвечает в VK и MAX. Наличие и цена **строго из прайса**; ИИ — только для нормализации мутных запросов, не источник фактов.

## Логика поиска бота

- Прайс целиком в памяти (8к строк — мизер), пересборка индекса при каждом обновлении.
- Поиск: по названию, артикулу, штрихкоду; нормализация (регистр, ё/е, пробелы); словарь синонимов (пополняемый клиентом); нечёткий поиск (опечатки).
- Широкий запрос («есть шайбы?») → бот группирует результат кодом и задаёт уточняющий вопрос (тип, размер), не вываливает сотню позиций и не шлёт их в ИИ.
- ИИ подключается только когда локальный поиск не справился или формулировка бытовая («шайба для машины»). ИИ переводит запрос и объясняет разницу, но не выдумывает наличие/цену.
- Где нужен физический замер/консультация — бот честно направляет к продавцу.
- **Мультиисточник прайса:** архитектура готова и к одной общей базе, и к двум раздельным (объединение по штрихкоду). Клиент ещё не решил вопрос локализации баз — бот подстроится под любой вариант.

## Принятые решения (ADR)

- n8n не используем → Node.js (гибче для поиска/синонимов).
- Polling, не webhook → домен и SSL не нужны.
- Прайс в памяти; SQL не обязателен (SQLite опционально, если нужно тонкое ранжирование).
- ИИ = переводчик запроса, не источник ответа. Цена/наличие только из файла.
- Мультиисточник прайса (готовность к раздельным базам магазинов).
- Формат файла `.xls` (BIFF) → парсер SheetJS (читает и xls, и xlsx).
- Файлы копятся на FTP по дате-времени → бот берёт самый свежий, позже авто-очистка старых.

## Открытые вопросы

- Названия магазинов для ответа покупателю (внутренние «Микрор-н» / «п.ш. Березовская» → как показывать).
- MAX: нужен **бот**, а не канал (клиент создал канал). Как создаётся бот в MAX + роль Госуслуг — проверить.
- Подтвердить при настройке, что `WFormat=11` даёт именно нужный прайс.
- Актуальность: обмен ночью → данные на конец прошлого дня. Клиент согласен (крупные остатки).
