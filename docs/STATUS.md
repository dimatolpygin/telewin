## Активная работа

**Этап**: 1 — Парсер прайса + CLI. Код написан и прогнан на реальных файлах, **ждёт проверки человеком**.
**Ветка**: `dev` (разработка), в `master` — только по явному указанию.

**Что сделано**: `src/price/раскладка.ts` (роли колонок, автоопределение), `src/price/парсер.ts`
(чтение `.xls`/`.xlsx`, сборка позиций), `src/price/ошибки.ts`, CLI `src/cli/price-parse.ts`.

**Как проверить руками** (базу поднимать не нужно):
```
npm run price:parse -- "samples/boevoy_прайс_2026-07-08.xls"     → 8 колонок, 11 888 позиций
npm run price:parse -- "samples/2026-07-06T06-25-47.xlsx"        → 11 колонок, 8 389 позиций
npm run price:parse -- "samples/пустышка_2026-07-13T08-39-49.xls" → 122 позиции + предупреждение
```

**Нетривиальное — прочитать до приёмки:**

- **Критерий про пустышку был неверен, исправлен в ROADMAP.** Считалось, что пустышка 50 КБ —
  битый файл и парсер должен «дать внятную ошибку». Скачали её с FTP и вскрыли: валидный .xls
  от Форы, правильная раскладка, 122 настоящих товара (один отдел, электрика). Ломать нечего —
  парсер разбирает её честно и вешает предупреждение. Блокировать такое обязан валидатор
  импорта на этапе 2 (порог строк + сравнение с прошлым), больше её ловить нечем.
- **Расхождение «общий ≠ сумма отделов» — массовое**: 572 позиции из 11 888 в боевом файле,
  630 из 8 389 в xlsx. Правило «не суммировать самим» подтверждено цифрами, не догадкой.
- **SheetJS молча парсит мусор**: текстовый файл и HTML-страницу с ошибкой он читает как
  таблицу из одной ячейки, не бросая исключения. Поэтому реальная защита от чужого файла —
  определение раскладки (ширина + типы ячеек), а не try/catch вокруг чтения.
- **`xlsx` поставлен с CDN SheetJS (`0.20.3`), а не с npm.** В npm-реестре пакет заброшен на
  `0.18.5` с prototype pollution (CVE-2023-30533) и ReDoS (CVE-2024-22363) — а через парсер
  проходит файл из внешнего источника. Версия и хеш зафиксированы в `package-lock.json`.
  **Следствие для этапа 9: сборка требует доступа к `cdn.sheetjs.com`** (проверено — `npm ci`
  в Docker проходит).
- **`logger.ts` отвязан от `config.ts`**: логгер требовал пароль от Postgres, чтобы напечатать
  строку, из-за чего CLI не запускался без базы. Теперь `LOG_LEVEL` читается из env напрямую.
  `/health` после правки проверен — 200, стек здоров.

- **tsx watch не видел правок**: Docker Desktop на Windows не пробрасывает inotify через
  bind mount. Правка доезжала в контейнер, но перезапуска не было. Лечится опросом файлов —

- **`drizzle-orm` поднят до `^0.45.2`**: ниже была SQL-инъекция через неэкранированные
  идентификаторы (GHSA-gpj5-g38j-94v9) — критично для поиска по вводу покупателя.
- **`.gitattributes`** держит LF в `docker/entrypoint.sh`: иначе Windows закоммитит CRLF
  и скрипт упадёт в Linux-контейнере (проверено: 0 символов CR в индексе).
- **`/health` отвечает 200 только если живы обе зависимости** — «здоров» без базы был бы враньём.
- `app_meta` — служебная таблица, нужна только чтобы доказать работу миграций.

## Протокол обновления

**При старте сессии**:
1. Прочитать этот файл.
2. `git tag -l "stage-*"` и сверить с колонкой «Закрывающий тег». Тег без записи в таблице = таблица устарела, обновить.
3. `git log --oneline -10` — что менялось последним.
4. Только после этого приступать к работе.

**При взятии этапа в работу**:
1. Обновить «Текущий этап» и «Активная работа».
2. Статус 🚧 в таблице.
3. Закоммитить отдельно: `chore(status): start stage N`.

**При закрытии этапа**:
1. Убедиться, что все чекбоксы в `ROADMAP.md` отмечены `[x]` и реально проверены человеком.
2. Создать тег: `git tag stage-N-done -m "<описание>"`.
3. В таблице: ✅, «Закрывающий тег», «Последний коммит» (`git rev-parse --short HEAD`), «Дата закрытия».
4. Добавить запись в «Историю закрытий».
5. Указать новый «Текущий этап» и «Следующий шаг».
6. Закоммитить: `chore(status): close stage N`.

**Если этап заблокирован**:
1. Статус ⏸ в таблице.
2. В «Известные блокеры»: что блокирует, кого ждём, что нужно для разблокировки.
