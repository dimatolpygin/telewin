# Автозапуск выгрузки прайса — диагностика

Тема: заставить «Мемо Фора» выгружать прайс на FTP по расписанию, без человека. Затянулась на несколько дней. Здесь собрано, что выяснили, чтобы не ходить по кругу.

Скрины клиента — в `assets/диагностика/`, ссылки в хронологии ниже.

## Как работает выгрузка

- Команда: `C:\Fora4S\fora.exe User="***" PASSWORD="***" mode=10 WFormat="11"`
- `User`/`PASSWORD` — вход в саму Фору (значения — в `доступы.txt`, вне репозитория). При неверных данных Фора пишет «имя и/или пароль неверны» и завершается.
- Формат «Прайс_1» (приоритет 11), XLS, кодировка 1251, галка «Без выдачи сообщений» — стоит ([скрин 04](../assets/диагностика/04_Фора_формат_галка_без_сообщений.png)).
- Отправка: FTP-строка `ftp://foraprice:***@87.58.210.46:21/price/`.
- ПК с Форой стоит в первом магазине. Клиент ходит на него по VPN/RDP. За ним локально работают продавцы. Пользователь Windows: `WIN-OR9D1UGTMS8\Евгений`. Часовой пояс UTC+7.

## Ключевой принцип

Фора — GUI-программа. Ей нужен ЖИВОЙ интерактивный рабочий стол Windows (отдельно от входа в саму Фору через User/PASSWORD). Стол даёт активная незаблокированная локальная сессия.

## Хронология ошибок (эволюция — каждый шаг ближе к цели)

1. **Задача виснет «Работает» / «выполняется в настоящее время».**
   [скрин 01](../assets/диагностика/01_журнал_задача_висит_Работает.png). Причина: запуск в неактивной сессии (отключённый RDP или спящий ПК) → нет рабочего стола → Фора висит, ждёт.
   Команда в задаче — [скрин 02](../assets/диагностика/02_задача_вкладка_Действия_команда.png), тип сессии «только для зарегистрированного пользователя» — [скрин 03](../assets/диагностика/03_задача_вкладка_Общие_тип_сессии.png).

2. **Ошибка `0x800710E0` «Оператор или администратор отклонили запрос».**
   [скрин 05](../assets/диагностика/05_ошибка_0x800710E0_оператор_отклонил.png). Питание клиент исключил. Причина — застрявший экземпляр от прошлых зависаний. Лечение: перезагрузка ПК.

3. **Ошибка `0x800702E4` «Запрошенная операция требует повышения».**
   [скрин 06](../assets/диагностика/06_ошибка_0x800702E4_требует_повышения.png), журнал сбоя 101/203 — [скрин 07](../assets/диагностика/07_журнал_101_203_сбой_запуска.png), [скрин 08](../assets/диагностика/08_журнал_107_203_101.png). Форе нужны права администратора. Лечение: галка «Выполнять с наивысшими правами» (вкладка «Общие»).

4. **Запуск успешен (0x0), но Фора отвергает логин.**
   [скрин 10](../assets/диагностика/10_успех_0x0_но_неверный_логин_work.png). В журнале полный успешный цикл (100 → 200 → 201 → 102), планировщик доволен. Но Фора показывает «Введённые имя и/или пароль пользователя являются неверными» ([скрин 09](../assets/диагностика/09_Фора_неверный_логин_пароль.png)) и завершается. Файл не выгружается.

## Что уже РЕШЕНО

- Права: галка «Выполнять с наивысшими правами». ОК.
- Застрявшие экземпляры: перезагрузка ПК. ОК.
- Условие питания: снято. ОК.
- Планировщик запускает задачу успешно (0x0), полный цикл, Фора реально стартует на живом столе. ОК.
- Режим задачи «только для зарегистрированного пользователя», галка «Без выдачи сообщений» — ОК.

## ТЕКУЩАЯ проблема — логин/пароль Форы из командной строки (открыта)

Фора не принимает `User="ае" PASSWORD="***"` из команды (пароль — в `доступы.txt`). Сообщение объединённое («имя И/ИЛИ пароль»), не различает, что именно не так.

Гипотезы:
1. Кириллический логин «ае» искажается при передаче через командную строку (кодировка) → Фора получает мусор.
2. Успех 10 июля был РУЧНЫМ запуском из уже открытой Форы, поэтому логин из команды тогда не проверялся, и это первая реальная проверка.
3. Сами данные могут быть неверны (клиент пробовал work/1 — не подошло, но такого юзера нет, это ничего не доказывает).

Следующий изолирующий шаг (не гадать):
- Клиент выходит из Форы и логинится вручную своей учёткой Форы («ае» + пароль из `доступы.txt`). Проходит ли вход?
  - Проходит → данные верные, проблема в передаче через команду → решение: завести в Форе пользователя с ЛАТИНСКИМ именем и цифровым паролем (обходит кодировку), либо запуск через .bat с `chcp 1251`.
  - Не проходит → данные неверны, искать реальные логин/пароль.

## Если удалённо не добить

Диагностика по скриншотам затянулась (много кругов). Быстрее — доступ по AnyDesk на ПК с Форой и наладка вживую.

## Расшифровка кодов журнала Task Scheduler

- 140 — настройки задачи сохранены (НЕ запуск)
- 107 — стартовала по расписанию; 110 — запущена пользователем
- 100 / 200 — задача / действие запущены; 201 — действие выполнено; 102 — задача завершена
- 101 / 203 — сбой запуска

## Проверка результата

Успех = новый файл в `/srv/foraprice/price/` на сервере после срабатывания задачи, без ручного касания Форы. Время клиента (UTC+7) минус 7 часов = UTC сервера.
